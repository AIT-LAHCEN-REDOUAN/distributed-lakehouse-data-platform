AdOptimizer CDP Chapter IV. Requirements Analysis and System Design
Each acceptance criterion is also expressed through an observable technical result. The
report therefore distinguishes between a service being reachable and a platform capability
being completed: successful ingestion must leave routed records and bronze artifacts,
raw loading must produce registered Iceberg tables, transformation must materialize
declared models, and validation must retain inspectable evidence. This evidence-oriented
formulation supports the traceability analysis in Appendix A and provides a consistent
basis for the validation campaign presented in Chapter VIII.

FR-1 Ingest heterogeneous customer-related
datasets through a structured pipeline.
The same configured ingestion process

FR-2 Provide topic-based transport for
reproducible raw data movement.
Kafka topics are created, used, and reset
through controlled pipeline operations, with
visible topic-based message flow.
FR-3 Persist replayable raw data in a distributed
bronze landing zone.
HDFS stores bronze artifacts in a durable,
distributed structure that can be re-read by
downstream Spark processing stages.
FR-4 Load bronze data into governed raw
lakehouse tables.
Spark reads the persisted bronze files and
writes Iceberg raw tables backed by Parquet
and registered through the shared catalog.
FR-5 Centralize analytical metadata for table
discovery and reuse.
Hive Metastore exposes the table definitions
required for downstream engines to identify
and access the lakehouse objects.
