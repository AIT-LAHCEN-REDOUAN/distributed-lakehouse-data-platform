CustomerDNA AI - Distributed Lakehouse Data Engineering Platform for Customer Analytics (AdOptimizer CDP)

Problem Statement: Customer-related data is fragmented across multiple heterogeneous sources (CSV/XLSX event, transaction, and campaign datasets), with inconsistent structure and quality. This fragmentation reduces reproducibility, makes operational ingestion difficult to audit and replay, and limits the ability to expose trusted analytical datasets for downstream analytics and future AI/ML use cases.

Proposed Solution: The project implements a distributed lakehouse-oriented Data Engineering platform that ingests datasets through Kafka, lands replayable bronze artifacts in HDFS, processes them with Spark into managed Iceberg tables registered in Hive Metastore, exposes SQL access through Trino, applies curated transformations through dbt-spark, validates data quality through Great Expectations (including HTML Data Docs evidence), orchestrates execution through Airflow, and monitors runtime behavior using Prometheus and Grafana.

Main Modules:
- Multi-source dataset organization for Client 1 under datasets/
- Kafka-based ingestion transport with dataset-specific topics
- HDFS bronze landing zone initialization and management
- Spark-based raw loading into Iceberg lakehouse tables
- Hive Metastore catalog for table discovery and interoperability
- Trino SQL access over Iceberg-backed lakehouse tables
- dbt-spark models for staging, intermediate, and analytics layers
- Great Expectations validations with stored results and Data Docs HTML
- Airflow orchestration through a multi-DAG operational sequence
- Observability stack (Prometheus, Grafana, custom pipeline metrics exporter)
- Deployment readiness: validated local Docker Compose baseline, with a preparation plan for multi-VM distributed deployment (control plane + data plane separation)

Expected Results:
- Reproducible end-to-end pipelines (ingestion -> bronze -> lakehouse -> curated analytics)
- Trusted analytical tables accessible through SQL
- Automated validation artifacts usable as report/defense evidence
- Operational observability (pipeline health + infrastructure signals)
- A reusable technical foundation for scaling toward larger workloads and future AI/ML consumers

Academic Contribution: The work contributes to Data Engineering by delivering an end-to-end distributed lakehouse pipeline that integrates event transport, distributed storage, distributed processing, table-format governance, SQL access, transformation governance, data quality automation, orchestration, and observability, with a clear path from local validation to multi-machine deployment.
