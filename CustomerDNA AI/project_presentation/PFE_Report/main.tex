\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}
\thispagestyle{empty}
This report presents the design and implementation of the \textbf{AdOptimizer Customer Data Platform}, a distributed data engineering platform built to centralize, govern, and expose multi-source customer datasets for trusted analytical use. The project addresses the challenge of integrating heterogeneous business data into a replayable, scalable, traceable, and observable architecture that can support enterprise analytics and future intelligent services.

The platform is developed as the \textbf{data engineering foundation of the broader AdOptimizer AI initiative}. In this wider vision, AdOptimizer AI targets intelligent advertising and customer-centric decision support, while the present project delivers the governed customer-data platform required to make such higher-level capabilities technically reliable and reusable.

The implemented solution is based on a complete Big Data engineering stack combining \textbf{Apache Kafka} as the ingestion backbone, \textbf{HDFS} as the bronze distributed storage layer, \textbf{Apache Spark} as the distributed processing engine, \textbf{Hive Metastore} as the metadata catalog, \textbf{Apache Iceberg} as the analytical table format, \textbf{Trino} as the SQL query engine, \textbf{Great Expectations} for data quality validation, \textbf{Apache Airflow} for orchestration, and \textbf{Prometheus} with \textbf{Grafana} for monitoring and observability.

The platform follows a distributed lakehouse architecture. Source datasets are first ingested through Kafka, landed into HDFS bronze storage, then processed by Spark and persisted as structured Iceberg tables registered in Hive Metastore. Trino provides analytical SQL access over the lakehouse, while Great Expectations enforces quality contracts and monitoring services provide visibility over infrastructure resources, processing behavior, and pipeline execution.

The final result is a reproducible, modular, and extensible platform aligned with modern data engineering and lakehouse practices. This project demonstrates how ingestion, distributed storage, distributed processing, metadata management, SQL analytics, orchestration, validation, and observability can be integrated into one coherent system. Beyond solving the immediate problem of customer-data centralization, the platform establishes a strong technical foundation for future analytics, dashboarding, and intelligent extensions.

\chapter{General Introduction}
\label{chap:introduction}

\section{Context}
Digital businesses increasingly depend on customer, behavioral, transactional, and campaign-related data to improve decision-making and optimize commercial performance. In the broader \textbf{AdOptimizer AI} vision, this need appears in the context of intelligent advertising, customer understanding, and future campaign optimization. However, these ambitions cannot be achieved directly if the underlying data remains fragmented, heterogeneous, poorly governed, and operationally difficult to trust.

Organizations therefore need robust data engineering platforms capable of centralizing multi-source customer data, preserving source traceability, structuring distributed storage and analytical layers, and guaranteeing data quality and observability. In this context, the \textbf{AdOptimizer Customer Data Platform} represents the data-engineering response: it is the implemented customer-data platform designed to serve as the technical foundation of the wider AdOptimizer AI initiative.

\section{Problem Statement}
The main challenge addressed in this project is the absence of a unified platform capable of collecting, structuring, validating, monitoring, and exposing multi-source customer data in a scalable and maintainable manner. Without a proper engineering pipeline, data remains fragmented, poorly governed, and difficult to reuse in analytics and future intelligent systems. For AdOptimizer AI in particular, this means that higher-level functions such as customer intelligence, analytics, and future decision support would lack a reliable and reusable data backbone.

\section{Objectives}
\begin{enumerate}[leftmargin=1.5em]
  \item Design a complete end-to-end data engineering architecture for multi-source customer data within the broader AdOptimizer AI vision.
  \item Implement a modern ingestion backbone using Apache Kafka.
  \item Introduce a bronze distributed storage layer using HDFS.
  \item Implement distributed processing jobs with Apache Spark.
  \item Build structured analytical tables with Apache Iceberg and register them through Hive Metastore.
  \item Expose analytical access through Trino.
  \item Integrate Great Expectations for data quality validation.
  \item Orchestrate the full workflow with Apache Airflow.
  \item Monitor infrastructure, lakehouse services, and pipeline health using Prometheus and Grafana.
  \item Establish the reusable customer-data foundation required for future analytics and intelligent modules in AdOptimizer AI.
\end{enumerate}

\section{Report Structure}
This report is organized into chapters covering the project context, state of the art, requirements analysis, architecture design, implementation, validation, results, and future perspectives.

\chapter{Host Organization and Project Context}
\label{chap:organization}

\section{Host Organization}
This project was carried out in an academic-professional context aligned with enterprise digital transformation needs. The host environment expects a solution that goes beyond isolated scripts and instead demonstrates a structured, deployment-oriented data platform capable of evolving toward real organizational use.

\section{Business Context}
The wider business context is defined by the \textbf{AdOptimizer AI} initiative, whose long-term goal is to support intelligent advertising, customer-centric analysis, and future optimization-oriented decision support. Such a vision requires a governed and reusable customer-data foundation.

The AdOptimizer Customer Data Platform answers this need by focusing on the upstream engineering problem: integrating heterogeneous customer-related datasets, preserving them across clear architectural layers, and exposing trusted data products for analytics and future intelligent use cases. In other words, AdOptimizer AI represents the broader strategic destination, while the AdOptimizer Customer Data Platform represents the concrete data-engineering platform that makes that destination technically feasible.

\section{Project Scope}
The current PFE phase focuses on the design and implementation of the \textbf{data engineering backbone}. This includes source ingestion, bronze persistence in HDFS, distributed processing with Spark, Iceberg lakehouse construction through Hive Metastore, SQL analytical access through Trino, quality validation, orchestration, and monitoring.

The current scope does not claim to implement the full final AdOptimizer AI product vision. Instead, it delivers the foundational platform on top of which future modules such as advanced campaign intelligence, recommendation services, broader application layers, or production AI services may later be built.

\section{Functional and Technical Requirements}
At a functional level, the platform must ingest heterogeneous datasets, preserve source identity, structure bronze and curated analytical layers, expose analytics-ready outputs, and support repeatable end-to-end execution.

At a technical level, it must guarantee traceability, modularity, data quality, rerunnability, observability, and deployment-oriented organization. These requirements are essential because the platform is intended to serve as a reliable foundation inside a broader intelligent-system roadmap.
