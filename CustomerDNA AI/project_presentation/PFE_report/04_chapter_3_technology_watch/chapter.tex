\chapter{Technology Watch}

\section{Introduction}
Chapter 2 established the conceptual logic behind distributed data platforms. This chapter moves to the concrete implementation layer by presenting the technologies retained for \projectname. The goal is not to produce exhaustive product documentation, but to explain why each selected tool deserves its place in the final platform and how the stack becomes coherent when these tools are assembled together.

\section{Selection Criteria}
\begin{itemize}
    \item \textbf{Distributed compatibility:} the tool had to fit a multi-node platform rather than a local-only demonstration.
    \item \textbf{Functional relevance:} each retained component had to answer a clear need in ingestion, storage, processing, governance, quality, orchestration, or observability.
    \item \textbf{Integration coherence:} the stack had to remain technically consistent across services and interfaces.
    \item \textbf{Operational defensibility:} the selected technologies had to support reproducibility, monitoring, and service separation.
    \item \textbf{Academic readability:} the final choices had to remain understandable and explainable in a final-year engineering report.
\end{itemize}

\section{Apache Kafka}
\begin{figure}[!htbp]
    \centering
    \includegraphics[width=0.18\textwidth]{90_assets/logos/Tech_logos/apache_kafka.png}
    \caption{Technology retained for event ingestion and topic-based transport}
    \label{fig:chapter3-kafka}
\end{figure}

\begin{itemize}
    \item \textbf{Role in the platform:} Apache Kafka acts as the ingestion backbone between dataset producers and downstream storage services \cite{apache_kafka_docs}.
    \item \textbf{Reason for selection:} it structures raw data transport through explicit topics and allows controlled replay when a stage must be re-executed.
    \item \textbf{Value for the project:} Kafka makes ingestion observable, modular, and better aligned with modern event-driven data engineering practices than direct one-shot file transfers.
\end{itemize}

\begin{itemize}

    \item \textbf{Reason for selection:} it offers distributed persistence, replication, and strong compatibility with the surrounding Hadoop and Spark ecosystem.
    \item \textbf{Value for the project:} HDFS gives the platform a real distributed storage layer instead of a local folder-based approximation, which strengthens the realism of the deployment.
\end{itemize}

\section{Synthesis of the Final Stack}
\begin{itemize}
    \item Kafka structures ingestion.
    \item HDFS persists the bronze layer in distributed storage.
    \item Iceberg and Hive Metastore organize the lakehouse tables and metadata.
    \item Spark executes the main distributed processing logic.
    \item Trino exposes interactive analytical querying.
    \item dbt governs transformations as explicit data models.
    \item Great Expectations formalizes data quality checks.
    \item Airflow orchestrates the end-to-end execution order.
    \item Prometheus and Grafana expose observability.
    \item Docker preserves deployment reproducibility and service isolation.
\end{itemize}
